# DESIGN.md template

Copy this to `DESIGN.md` (or `docs/DESIGN.md`) in the app's repo and fill every part. One page. If a part does not apply, write why.

```markdown
# <App name> design language

Status: <draft | agreed on DATE>

## Genre
<Quiet | Character | Atmosphere | Data | Loud>. One sentence on the job people
open the app to do. If a second genre rides inside, name it and say which
wins the background and layout and which wins the type.

## The one material
<The object, photograph, character or texture nobody else owns, and every
place it appears: icon, first screen, paywall, widget. What must never stand
in for it.>

## The signature moment
<The one moment that is allowed to be loud. What stays calm so it can be.>

## Colour means something
| Colour | Token | Meaning | Never |
|---|---|---|---|
| | | | |

One selected colour app-wide. Text colour on each fill, with its contrast.

## Type, spacing, corners
<One family and its scale. One spacing scale. One corner scale. Where the
tokens live in code.>

## Numbers
<Which screens have a hero number, how it changes, and the sentence that
follows it.>

## Motion
<The spring or easing voices and where they live. The Reduce Motion form.>

## Voice
<Who is speaking. Two examples of right and wrong. The decline phrase.>

## The moments that get skipped
- Empty: <what is true, what to do next>
- Error: <what failed, the way out>
- Win: <what celebrates, and that nothing else does>

## Surfaces
<Widget families, Live Activity, notifications: what each shows in one
number and one action.>

## Build order for new features
Widget and Live Activity, then the notification, then the in-app screen.

## Wide and folded windows
<How the genre uses an iPad or an unfolded phone. Not a centred column.>
```

## Checks before calling it done

- Every colour in the table has a meaning a stranger could apply.
- A new screen could be built from this page without asking a question.
- Nothing on the page is true of every app in the category.
