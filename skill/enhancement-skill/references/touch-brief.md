# The Touch Brief

The brief is written from the person's side. Fill each field from the code and copy first; ask the user only for what you can't infer (three questions at most). Save it as `TOUCH.md` at the project root.

## Template

```markdown
# Touch Brief: <App name>

## The person
<One specific human, not a segment. "A night-shift nurse checking a dose between rooms", not "healthcare professionals".>

## The moment
<When and where they open the app, how long they stay, one hand or two, what else is competing for them.>

## The feeling
<The one feeling they should leave with, in their words: "handled", "proud", "calmer than before".>

## What must never happen
<The failure that would break trust: a wrong number, a lost entry, a patronising tone, a noisy notification.>

## Signature moment
<The single moment worth designing hardest: first run, the daily check-in, completion, sharing.>

## Existing world
<Brand colors, fonts, icon, tone of voice, anything the team has already committed to. "None" is an answer.>

## Traits
| Trait | Value | Why |
|---|---|---|
| energy (0 calm … 1 lively) | 0.0 | |
| warmth (0 cool … 1 warm) | 0.0 | |
| craft (0 machined … 1 handmade) | 0.0 | |
| stakes (low / everyday / high) | | |
| moment (glance / task / linger / play) | | |
| assistant (none / quiet / character) | | |
```

## Reading traits from evidence

| Evidence | Pushes toward |
|---|---|
| Money, health, legal, safety, work data, irreversible actions | stakes `high` |
| Games, kids, hobbies, collections, stickers | stakes `low`, craft up, energy up |
| Widgets, complications, timers, one-number screens | moment `glance` |
| Journals, reading, meditation, sleep, recipes | moment `linger`, energy down, warmth up |
| Forms, lists, converters, scanners, admin | moment `task` |
| Drawing, music making, building, puzzles | moment `play`, craft up |
| Copy with "you", jokes, first names, emoji | warmth up |
| Copy with numbers, units, status codes | warmth down |
| Streaks, workouts, countdowns, launches | energy up |
| Chat UI, "ask", named assistant, voice mode | assistant `character` |
| AI summaries, suggestions, search, auto-tagging with no chat | assistant `quiet` |

## Questions worth asking (pick up to three)

1. Picture one person using it. Who are they, and what were they doing a minute before they opened it?
2. When they close the app, what should they feel?
3. Is there anything already fixed: a brand color, a font, a mascot, a tone?
4. What would make them stop trusting it?

Don't ask about styles by name. People describe feelings well and aesthetics badly; the mapping turns feelings into a style.
